one in `domum-core/backlog/`. Restructured 2026-07-21 after a second audit
pass: tasks 18–40 were added and the priority grouping was replaced by the

session. Work the phases in order.

Sibling repo: `domum-core` (Raspberry Pi 5). The repos stay separate forever;
tasks marked **[shared-philosophy]** move this repo toward the common
foundation. domum-core is the pattern *reference* — port from it, never
modify it from here, and never copy its known defects (unprefixed
named-volume backups, manifest-written-before-exports; the relevant tasks
call these out).

## Deliberately NOT tasks (leave alone)

- The btrfs snapshot + health-check + auto-rollback update pipeline — this is
  the best pattern in either repo. Tasks 22/23/24 fix its real gaps (gate
  bypass, silent snapshot no-op, missing image restore); don't rework the
  pipeline itself.
- The Immich bundle manager — fragile-looking (parses upstream compose) but
  guarded, and matched-bundle updates are the correct model for Immich.
- `restic` repo identity pinning, NFS/FTP target types, deep checks — keep.
- Kubernetes, Ansible, metrics stacks, or any new orchestration layer —
  Bash + Compose + systemd is adequate and stays.

## Ground rules

- Never rewrite working code for style alone.
- Every change must pass: `bash -n`, `shellcheck --severity=warning`,
  `tests/immich-secret-propagation-smoke.sh`, and the compose config CI step.
- The N100 is a production host with the family photo library. Anything
  touching Immich, snapshots, or restore paths needs a dry-run and a
  rollback note before merge.
- Tasks marked **Operator: yes** must ship an `## Operator runbook` section
  and must never be auto-applied by timers — the repo change lands first,
  the host step runs only when Franco schedules it.
